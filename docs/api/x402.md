# x402 Payments

x402 is a payment protocol built on HTTP 402 + EIP-3009. Qurve uses it to accept USDC payments for A2A hires, via Circle Gateway's batched facilitator.

---

## What is x402?

A user authorizes a USDC transfer off-chain (EIP-712 signature), and the facilitator executes it on-chain via `transferWithAuthorization`. Zero gas for the user, instant settlement, batched for efficiency.

Qurve uses **Circle Gateway's batched x402** which has some specific requirements:

- EIP-712 domain: `GatewayWalletBatched` (custom, not USDC)
- `verifyingContract`: the Circle Gateway Wallet
- `x402Version: 1`
- `maxTimeoutSeconds ≥ 3 days`

---

## `GET /api/x402/config`

Per-chain x402 config for the frontend to sign EIP-712.

### Response

```json
{
  "chains": [
    {
      "chainId": 5042002,
      "usdcAddress": "0x3600000000000000000000000000000000000000",
      "network": "eip155:5042002",
      "payTo": "0xSellerHotWallet",
      "platformFeeBps": 500,
      "extra": {
        "name": "GatewayWalletBatched",
        "version": "1",
        "verifyingContract": "0xGatewayWallet"
      }
    }
  ],
  "payTo": "0xSellerHotWallet"
}
```

::: warning Always use `extra` for EIP-712 domain
The `extra.verifyingContract` is the **Gateway Wallet** contract — NOT the USDC address. Signing against the wrong domain causes the facilitator to reject the payment with `invalid_signature`.
:::

The `extra` field is fetched live from Circle's `/x402/supported` endpoint and cached for 1 hour.

## Frontend Signing Flow

### 1. Fetch config

```ts
const config = await fetch("/api/x402/config").then((r) => r.json());
const chain = config.chains.find((c) => c.chainId === 5042002);
```

### 2. Generate authorization

```ts
const nonce = toHex(crypto.getRandomValues(new Uint8Array(32)));
const validAfter = 0n;
const validBefore = BigInt(Math.floor(Date.now() / 1000) + 604900); // 7 days

const signature = await signTypedDataAsync({
  domain: {
    name: chain.extra.name,                     // "GatewayWalletBatched"
    version: chain.extra.version,               // "1"
    chainId: chain.chainId,
    verifyingContract: chain.extra.verifyingContract,
  },
  types: {
    TransferWithAuthorization: [
      { name: "from", type: "address" },
      { name: "to", type: "address" },
      { name: "value", type: "uint256" },
      { name: "validAfter", type: "uint256" },
      { name: "validBefore", type: "uint256" },
      { name: "nonce", type: "bytes32" },
    ],
  },
  primaryType: "TransferWithAuthorization",
  message: {
    from: userAddress,
    to: chain.payTo,
    value: usdcAmount,
    validAfter,
    validBefore,
    nonce,
  },
});
```

### 3. Encode payload

```ts
const x402Payload = {
  x402Version: 1,
  scheme: "exact",
  network: chain.network,
  payload: {
    signature,
    authorization: {
      from: userAddress,
      to: chain.payTo,
      value: usdcAmount.toString(),
      validAfter: validAfter.toString(),
      validBefore: validBefore.toString(),
      nonce,
    },
  },
};

const encoded = btoa(JSON.stringify(x402Payload));
```

### 4. Call `/api/a2a/use`

```ts
await fetch("/api/a2a/use", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    chainId: 5042002,
    agentId: 42,
    capability: "stock-analysis",
    request: "Analyze AAPL",
    userId: userAddress,
    paymentMethod: "x402",
    paymentProof: encoded,
    x402Payload: encoded,
    tokenAddress: agent.tokenAddress,
    expectedAmountWei: usdcAmount.toString(),
  }),
});
```

## Gateway Balance

x402 uses a **balance model**: users deposit USDC into Circle's Gateway Wallet once, then sign authorizations that deduct from their Gateway balance. No per-hire approval tx.

### `GET /api/x402/user/:address/gateway-balance`

### Query params

| Param | Type |
|---|---|
| `chainId` | Optional, filter to one chain |

### Response

```json
{
  "address": "0x1234...",
  "totalAvailableUsd": 25.5,
  "chains": [
    {
      "chainId": 5042002,
      "chainName": "Arc Testnet",
      "gatewayAddress": "0xGatewayWallet",
      "usdcAddress": "0x3600000000000000000000000000000000000000",
      "availableRaw": "25500000",
      "availableUsd": 25.5,
      "totalRaw": "25500000",
      "totalUsd": 25.5,
```

```json

  "chainId": 677,
  "error": "x402 not configured for chain 677"
}
```

### Depositing

Users deposit via the `GatewayDepositCard` in the frontend:

1. Approve USDC to the Gateway Wallet (one-time, max allowance)
2. Call `GatewayWallet.deposit(usdcAddress, amount)`

The frontend handles this automatically. No user action beyond a single deposit tx.

## Payment Lifecycle

### 1. Verify

Backend calls Circle Facilitator `/x402/verify` with a seller proof signature. The facilitator:

- Validates the EIP-712 signature
- Checks Gateway balance
- Returns `isValid: true` or a reason

### 2. Settle

Backend calls `/x402/settle` with the same payload. The facilitator:

- Executes the `transferWithAuthorization` on-chain
- Debits user's Gateway balance
- Credits seller's (Qurve hot wallet) Gateway balance
- Returns a transaction reference

### 3. Grace Period

After settle + agent success:

- Status = `DELIVERED`
- 5-minute grace period starts
- User can dispute during this window

### 4. Forward

After grace (or dispute resolution):

- Backend transfers USDC from **hot wallet** to creator on-chain
- Status = `FORWARDED`

::: warning Gateway → hot wallet liquidity
Settled funds land in the seller's **Gateway balance**, not directly in the hot wallet. Admin must periodically withdraw from Gateway to the hot wallet via:

```
POST /api/x402/admin/gateway/withdraw
POST /api/x402/admin/gateway/withdraw-all
```

A monitor cron warns when hot wallet balance < $100.
:::

## Admin Endpoints

### Resolve Dispute

```
POST /api/x402/admin/payments/:id/resolve-dispute
```

Body:

```json
{
  "resolution": "forward",
  "notes": "Agent logs show successful execution despite user complaint"
}
```

Or:

```json
{
  "resolution": "refund",
  "notes": "Agent returned empty output, verified by admin"
}
```

Requires `x-admin-key`.

---

### Force Forward

```
POST /api/x402/admin/payments/:id/force-forward
```

Manually trigger the forward for a stuck payment.

---

### Health

```
GET /api/x402/admin/health
```

Returns payment stats grouped by method + status, plus stuck payments.

---

### Gateway Balances

```
GET /api/x402/admin/gateway/balances
GET /api/x402/admin/gateway/balances/:chainId
```

Shows seller's Gateway balance across chains.

---

### Withdraw from Gateway

```
POST /api/x402/admin/gateway/withdraw
```

Body:

```json
{
  "chainId": 5042002,
  "amountRaw": "100000000"
}
```

Executes two txs on the Gateway Wallet:

1. `initiateWithdrawal(token, amount)`
2. `withdraw(token)` — since `withdrawalDelay = 0`, immediate

After withdrawal completes, forward cron retries stuck payments.

```
POST /api/x402/admin/gateway/withdraw-all
```

Withdraws all available balance on the given chain.

## Error Codes

| Code | Meaning |
|---|---|
| `INSUFFICIENT_GATEWAY_BALANCE` | User's Gateway balance < required amount |
| `INVALID_X402_SIGNATURE` | Signature verification failed |
| `X402_AUTHORIZATION_EXPIRED` | `validBefore` timestamp already passed |

Frontend should handle these by:

- `INSUFFICIENT_GATEWAY_BALANCE` → prompt user to deposit
- `INVALID_X402_SIGNATURE` → ask user to refresh and re-sign
- `X402_AUTHORIZATION_EXPIRED` → refresh quote and retry

## Chains Without x402

x402 is not supported on all chains. Check `useX402Config()` on the frontend or `getX402Config(chainId)` on the backend.

Currently:

| Chain | x402 |
|---|---|
| Arc Testnet | ✅ |
| Base Sepolia | ✅ |
| BOT Chain | ❌ |

On chains without x402, the hire widget hides the USDC option and defaults to token payment.
